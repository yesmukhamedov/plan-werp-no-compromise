# EPIC-006. Инвентаризация ролей и прав

## Зачем

Модель доступа сейчас склеена из трёх схем: собственный `auth-server`, ABAC
внутри домена `dit`, `PermissionService` в `main-module`, плюс проверки,
написанные руками в контроллерах
([P-09](../docs/00-context/02-pain-points.md#p-09-авторизация-склеена-из-трёх-схем)).

Единой точки, отвечающей на вопрос «имеет ли пользователь право на это
действие», не существует. Значит, никто не может ответить и на вопрос «что
изменится в правах после переезда» — а это вопрос, который зададут первым.

За 12 лет накоплена бизнес-логика прав, которую нельзя выбросить, но и
переносить как есть нельзя.

## Результат

Полный реестр ролей и прав с решением по каждому и соответствием целевой модели
([ADR-0006](../docs/02-decisions/ADR-0006-auth-model.md)).

## Задачи

### TASK-0601. Собрать реестр ролей

Все роли, их назначение, число пользователей в каждой, кто выдаёт.

**Приёмка:** реестр полон; роли без пользователей помечены.

### TASK-0602. Собрать реестр прав

Все права из всех трёх механизмов, включая проверки, написанные руками в
контроллерах.

**Приёмка:** реестр полон; для каждого права указан механизм, которым оно
проверяется, и место в коде.

### TASK-0603. Описать ограничение по области данных

Как сейчас работает разграничение по филиалу, компании, подразделению: где
применяется, где забыто, какие есть исключения.

**Приёмка:** правила описаны; обнаруженные пропуски зафиксированы как находки
безопасности ([EPIC-010](EPIC-010-security-audit.md)).

> Ограничение области данных, применяемое в контроллере, легко забыть — и
> обнаружить это можно только целенаправленной проверкой.

### TASK-0604. Связать права с эндпойнтами

Для каждого эндпойнта из [EPIC-002](EPIC-002-contract-inventory.md) — какое право
требуется.

**Приёмка:** таблица «эндпойнт → право» полна; эндпойнты без явной проверки прав
выявлены и перечислены отдельно.

### TASK-0605. Связать права с меню и навигацией

Сейчас меню строится из прав (`/current-user/routes`). Это поведение
сохраняется, но получает единый источник.

**Приёмка:** соответствие «право → пункт меню» описано.

### TASK-0606. Определить живость

Права, не назначенные никому; роли без пользователей; проверки, которые никогда
не срабатывают.

**Приёмка:** каждое право помечено как живое / мёртвое; решение по мёртвым
принято владельцем.

### TASK-0607. Спроектировать целевую модель

Роль / право / область данных / владение по
[ADR-0006](../docs/02-decisions/ADR-0006-auth-model.md); соответствие «старое
право → новое».

**Приёмка:** модель описана; каждое переносимое право имеет соответствие; права
объявлены в спецификации API.

## Критерии закрытия эпика

- [ ] Реестры ролей и прав полны
- [ ] Ограничение по области данных описано, пропуски выявлены
- [ ] Каждый эндпойнт связан с правом
- [ ] Мёртвые права и роли отсеяны
- [ ] Целевая модель спроектирована
- [ ] Права объявлены в спецификации API ([NC-12](../docs/01-principles/01-no-compromise.md#nc-12))
