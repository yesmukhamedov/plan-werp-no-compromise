# Бэкенд

Из чего состоит серверная часть: модули, слои, классы. Правила — здесь, полный
состав классов по доменам — в [spec/](spec/README.md).

Конкретные технологии не названы: решение по стеку отложено
([ADR-0003](../docs/02-decisions/ADR-0003-backend-stack.md)). Всё описанное
выполнимо на любом кандидате; зависимые места помечены `[STACK]`.

# Часть I. Правила

## Развёртываемые единицы

Одна ([ADR-0008](../docs/02-decisions/ADR-0008-modular-monolith.md)):

| Единица | Что | Почему отдельно |
|---|---|---|
| `werp-app` | всё приложение: платформа + 13 доменов | — |
| `werp-worker` | фоновые задачи | другой профиль нагрузки; **та же кодовая база**, другой режим запуска |

`werp-worker` — не отдельный проект. Это тот же артефакт, запущенный с другим
профилем.

## Структура модуля

Каждый доменный модуль имеет одинаковую форму:

```
<domain>/
  README.md              назначение, публичный интерфейс, инварианты, как тестировать
  api/                   ПУБЛИЧНЫЙ интерфейс модуля — единственное, что видно снаружи
    <Domain>Facade       операции, доступные другим доменам
    dto/                 типы, которыми модуль обменивается с другими доменами
    event/               доменные события, которые модуль публикует
  domain/                бизнес-логика; не зависит ни от чего внешнего
    model/               сущности и объекты-значения
    rule/                правила и инварианты
    <Domain>Service      доменные операции
  application/           сценарии; границы транзакций; авторизация
    <UseCase>Handler     один сценарий — один обработчик
  adapter/
    web/                 HTTP: контроллеры, генерируемые из спецификации API
      <Resource>Controller
    persistence/         хранилище
      <Entity>Repository
      <Entity>Record     представление строки таблицы
    external/            внешние системы
  test/
```

**Правило зависимостей — внутрь, никогда наружу:**

```
adapter  →  application  →  domain
   │                          ▲
   └──────── api ─────────────┘
```

`domain` не знает ни про HTTP, ни про базу. Это единственное, что делает его
тестируемым без контейнера и без базы.

## Что видно снаружи модуля

Только содержимое `api/`. Всё остальное недоступно технически `[STACK]`, а не
по договорённости.

Другой домен **не может**: внедрить репозиторий, импортировать сущность,
прочитать таблицу, вызвать сервис напрямую. Попытка обнаруживается тестом
архитектурных правил и блокирует слияние
([NC-02](../docs/01-principles/01-no-compromise.md#nc-02)).

## Типы классов

| Тип | Суффикс | Ответственность | Состояние | Лимит строк |
|---|---|---|---|---|
| Фасад | `Facade` | публичные операции модуля | нет | 200 |
| Обработчик сценария | `Handler` | один сценарий, границы транзакции | нет | 150 |
| Доменный сервис | `Service` | операция над несколькими сущностями | нет | 300 |
| Сущность | — | состояние + инварианты | да | 300 |
| Объект-значение | — | неизменяемое значение | да | 100 |
| Правило | `Rule` / `Policy` | одно бизнес-правило | нет | 100 |
| Репозиторий | `Repository` | доступ к своим таблицам | нет | 300 |
| Контроллер | `Controller` | только транспорт | нет | 200 |
| Преобразователь | `Mapper` | между слоями | нет | 200 |
| Событие | `Event` | факт, произошедший в домене | да (неизм.) | 50 |
| Подписчик | `Listener` | реакция на чужое событие | нет | 150 |

Лимиты — верхняя граница, а не цель
([NC-04](../docs/01-principles/01-no-compromise.md#nc-04)). Общий предел класса —
400 строк, метода — 50, зависимостей класса — 7; всё проверяется линтером.

**Класса с именем `*Util`, `*Helper`, `*Manager`, `*Common` в системе не
существует.** Такие имена означают «сюда складывают то, чему не нашли места», и
именно так вырастают модули, из которых потом нельзя ничего извлечь.

## Правила классов

1. **Зависимости в конструкторе, неизменяемые.** Полевая инъекция запрещена и
   проверяется статически ([NC-03](../docs/01-principles/01-no-compromise.md#nc-03)).
2. **Один класс — одна причина меняться.** Контроллер меняется при изменении
   транспорта, обработчик — при изменении сценария, сущность — при изменении
   правил.
3. **Контроллер не содержит логики.** Разобрать запрос, вызвать обработчик,
   вернуть ответ. Если в контроллере есть `if` по бизнес-условию — он не на
   своём месте.
4. **Сущность защищает свои инварианты.** Сущность в некорректном состоянии
   невозможно создать; сеттеров, позволяющих его нарушить, нет.
5. **Транзакция начинается и заканчивается в обработчике сценария.** Не в
   контроллере, не в репозитории, не в доменном сервисе.
6. **Репозиторий возвращает доменные объекты**, а не строки таблицы.

## Доступ к данным

**Один механизм на всю систему** `[STACK]`,
[NC-05](../docs/01-principles/01-no-compromise.md#nc-05). Второго не существует.

- Запросы типобезопасны; конкатенация SQL запрещена и проверяется.
- Сырой SQL допускается только в выделенном слое запросов чтения (отчёты,
  сводные выборки), только параметризованный, с обоснованием.
- Ленивая загрузка через границу агрегата запрещена — она и есть источник
  проблемы N+1.
- Каждый запрос списка постраничен на уровне SQL, а не в памяти.

## Междоменное взаимодействие

Два способа, третьего нет:

| Способ | Когда | Транзакция |
|---|---|---|
| Вызов `Facade` другого домена | результат нужен сейчас, операция логически едина | общая |
| Публикация события | другой домен должен отреагировать, результат не нужен | публикация в транзакции источника, обработка отдельно |

Событие публикуется через транзакционный исходящий журнал: оно не может
потеряться при откате транзакции и не может быть опубликовано, если транзакция
не завершилась.

## Платформа

Модули, от которых зависят все домены и которые не зависят ни от одного.
Пишутся в [Фазе 1](../transition/plan/02-phase-1-platform.md) до доменной
разработки.

| Модуль | Ответственность | Ключевые классы |
|---|---|---|
| `platform-access` | аутентификация, права, область данных | `PermissionEvaluator`, `DataScopeResolver`, `CurrentUser` |
| `platform-audit` | неизменяемый журнал изменений | `AuditWriter`, `AuditableRegistry` |
| `platform-report` | шаблоны, формирование, асинхронное исполнение | `ReportRunner`, `ReportTemplate`, `ExcelWriter`, `PdfWriter` |
| `platform-file` | загрузка, хранение, выдача, срок жизни | `FileStore`, `FileAccessPolicy` |
| `platform-notification` | почта, SMS, мессенджеры, уведомления в интерфейсе | `NotificationSender`, `NotificationTemplate` |
| `platform-task` | расписание, очередь, повторы, идемпотентность | `TaskScheduler`, `TaskRunner`, `IdempotencyKey` |
| `platform-observability` | журналы, метрики, трассировка | `RequestContext`, `TraceId` |
| `platform-error` | единая модель ошибки, локализация | `DomainException`, `ErrorCode`, `ErrorResponseFactory` |
| `platform-i18n` | сообщения на трёх языках | `MessageResolver`, `LocaleResolver` |
| `platform-money` | десятичная арифметика, валюты, округление | `Money`, `Currency`, `ExchangeRate`, `RoundingPolicy` |
| `platform-outbox` | транзакционная публикация событий | `OutboxWriter`, `OutboxPublisher` |
| `platform-changelog` | журнал операций для отката переезда | `OperationLogWriter` |

Последний модуль не нужен ни одному домену и нужен ровно один раз — в ночь
переезда ([transition/08-rollback.md](../transition/08-rollback.md#о2-поздний-откат)).
Поэтому он в платформе: иначе его забудут.

## Обработка ошибок

- Одна иерархия исключений; доменное исключение несёт машиночитаемый код.
- Исключение не «проглатывается»: либо обрабатывается, либо пробрасывается с
  контекстом.
- Преобразование в HTTP-ответ — **в одном месте**, а не в каждом контроллере.
- Клиенту не уходит стек вызовов, имя класса, текст SQL, имя таблицы.
