# Продукт

**Здесь описан только результат.** Каким будет новый WERP: какие таблицы с
какими колонками и индексами, какие модули и классы, какие эндпойнты, какие
страницы и компоненты.

В этом разделе **нет ни слова о том, как мы туда переходим** — ни о легаси, ни
о миграции, ни о фазах. Связь существующего с целевым — в
[transition/](../transition/README.md).

Разделение сделано намеренно: документ, который одновременно описывает целевую
систему и объясняет, откуда взялась каждая её часть, невозможно читать ни
разработчику (ему нужен только результат), ни тому, кто планирует переход (ему
нужны соответствия). Через год после переезда весь `transition/` архивируется,
а `product/` останется документацией системы.

## Правила этого раздела

1. **Только результат.** Формулировки «сейчас это работает так, а будет иначе»
   здесь запрещены — они относятся к [transition/](../transition/README.md).
   Читатель `product/` не обязан знать, что существовала предыдущая система.

2. **Конкретность.** «Таблица договоров с необходимыми полями» — не
   спецификация. Спецификация — это список колонок с типами, ограничениями и
   индексами.

3. **Уровни зрелости.** Каждый артефакт в реестре имеет статус:

   | Статус | Значение |
   |---|---|
   | `спроектирован` | спецификация полна, можно писать код |
   | `набросок` | состав известен, детали не проработаны |
   | `объявлен` | известно, что артефакт нужен, больше ничего |

   Реализация артефакта не начинается, пока он не `спроектирован`.

4. **Стек-нейтральность.** Решение по стеку бэкенда отложено
   ([ADR-0003](../docs/02-decisions/ADR-0003-backend-stack.md)). Зависимые от
   него места помечены `[STACK]` и уточняются после гейта G1. Схема данных,
   контракт API и состав страниц от стека не зависят и проектируются уже сейчас.

5. **Источник истины.** При расхождении между этим разделом и любым другим
   документом прав `product/`: он описывает то, что строится.

## Что здесь ещё не заполнено

Реестры содержат строки со статусом `объявлен` — это честное состояние на
сегодня, а не недоработка: наполнение реестров и есть работа Фазы 0
([EPIC-002](../backlog/EPIC-002-contract-inventory.md),
[EPIC-003](../backlog/EPIC-003-schema-inventory.md),
[EPIC-007](../backlog/EPIC-007-reports-inventory.md),
[EPIC-011](../backlog/EPIC-011-scenario-registry.md)).

Формат и глубина зафиксированы полностью — на примере домена D1
([spec/D1-reference.md](spec/D1-reference.md)). Остальные домены заполняются по
этому образцу.
