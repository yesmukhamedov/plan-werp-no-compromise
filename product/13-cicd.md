# CI/CD

## Принципы

1. **В прод попадает только то, что прошло пайплайн** ([NC-13](../docs/01-principles/01-no-compromise.md#nc-13)).
   Ручной деплой невозможен технически: права на изменение окружения есть только
   у сервисной учётной записи CI.
2. **Пайплайн выкатывает всё**, а не один компонент.
3. **Тесты отключить нельзя.** Флаги пропуска тестов не существуют в
   конфигурации сборки; их отсутствие проверяется.
4. **Один артефакт на все контуры** ([NC-11](../docs/01-principles/01-no-compromise.md#nc-11)).
5. **Быстро.** Медленный пайплайн начинают обходить, а обойдённый пайплайн не
   выполняет NC-13.

## Конвейер

```
PR открыт
   │
   ├─ сборка в чистом контейнере, без кэша артефактов        NC-08
   ├─ линтеры и форматирование
   ├─ модульные тесты
   ├─ интеграционные тесты (PostgreSQL в контейнере)
   ├─ контрактные тесты против спецификации                  ADR-0005
   ├─ тест архитектурных правил                              NC-02
   ├─ проверка покрытия (порог + отсутствие снижения)        NC-01
   ├─ статический анализ, включая анализ безопасности
   ├─ сканирование уязвимостей зависимостей                  NC-09
   ├─ проверка обратной совместимости спецификации API
   ├─ проверка реестра разрешённых библиотек                 NC-14
   ├─ проверка на запрещённые конструкции
   │    System.out / printStackTrace / console.log           NC-10
   │    IP-адреса и имена хостов                             NC-11
   │    конкатенация SQL                                     NC-05
   │    полевая инъекция                                     NC-03
   │    секреты
   └─ проверка размеров классов и методов                    NC-04
   │
   ▼
слияние в main
   │
   ├─ сборка образа, формирование SBOM
   ├─ подпись образа
   ├─ развёртывание в dev
   ├─ дымовые тесты
   ├─ развёртывание в stage
   ├─ сквозные тесты
   ├─ нагрузочный прогон (по расписанию)
   │
   ▼
развёртывание в prod (с подтверждением)
   ├─ миграции схемы
   ├─ развёртывание без простоя
   ├─ дымовые тесты
   └─ автоматический откат при отказе дымовых тестов
```

**Каждая проверка в списке исполняет конкретное правило машиной.** Это не
«best practices вообще» — это [NC-01…NC-15](../docs/01-principles/01-no-compromise.md)
в исполняемом виде.

## Бюджет времени

| Этап | Бюджет |
|---|---|
| Проверки на PR | ≤ 15 мин |
| От слияния до dev | ≤ 10 мин |
| От слияния до stage | ≤ 30 мин |
| Развёртывание в prod | ≤ 15 мин |

Превышение — задача с приоритетом, а не данность. Монорепозиторий
([ADR-0007](../docs/02-decisions/ADR-0007-repo-layout.md)) требует сборки только
затронутого изменением и работающего кэша — иначе бюджет не выдержать.

## Миграции схемы в пайплайне

- Применяются автоматически перед развёртыванием.
- Отработаны на копии промышленных данных до слияния.
- Совместимы с предыдущей версией приложения — иначе развёртывание без простоя
  невозможно.
- Ломающие изменения — в четыре шага, каждый в отдельном релизе
  ([product/03-database.md](03-database.md#миграции)).

## Ветвление и релизы

- Короткоживущие ветки, PR, защищённый `main`.
- Conventional Commits; журнал изменений собирается автоматически.
- Одна версия на монорепозиторий; тег на весь репозиторий.
- Образ помечается версией и хешем коммита; артефакт прослеживается до
  исходного кода.

## Особенности периода переезда

- Пайплайн **репетиции миграции**: развернуть чистый контур, восстановить копию
  промышленных данных, прогнать миграцию, выполнить сверку, опубликовать отчёт.
  Запускается по кнопке и по расписанию.
- Пайплайн **теневого прогона**: обновление копии данных, перезапуск сравнения.
- Пайплайн **отката**: отрепетирован и измерен ([transition/08-rollback.md](../transition/08-rollback.md)).

Все три — обычные пайплайны в репозитории, а не набор действий по инструкции.
Процедура, выполняемая руками в три часа ночи, выполняется с ошибками.
