# Окружения

## Контуры

| Контур | Назначение | Данные | Кто разворачивает |
|---|---|---|---|
| **Локальный** | разработка | синтетические | разработчик, одна команда |
| **Dev** | интеграция изменений | синтетические | CI автоматически из `main` |
| **Stage (предпродуктивный)** | приёмка, нагрузка, репетиции, теневой прогон, демонстрации | **обезличенная копия промышленных** | CI |
| **Prod** | эксплуатация | промышленные | CI, с подтверждением |

### Локальный контур

`git clone` + одна команда = работающая система, включая PostgreSQL в
контейнере ([NC-08](../docs/01-principles/01-no-compromise.md#nc-08)). Никаких
файлов из локальных папок, никакой ручной установки драйверов, никаких
скриптов запуска, привязанных к конкретной машине.

Если локальный запуск сложнее одной команды — это дефект платформы.

### Предпродуктивный контур

Ключевой контур проекта: при выбранной стратегии перехода он заменяет собой
прод как источник обратной связи на весь срок разработки
([ADR-0001](../docs/02-decisions/ADR-0001-strategy-big-bang.md)):

- копия промышленных данных, регулярно обновляемая и **обезличенная**;
- на нём идёт теневой прогон ([transition/06-parity-verification.md](../transition/06-parity-verification.md));
- на нём проводятся репетиции миграции;
- на нём проходят демонстрации пользователям раз в две недели;
- на нём выполняются нагрузочные испытания.

Требования к ресурсам сопоставимы с промышленным контуром — это статья затрат,
которую нужно заложить с самого начала.

## Конфигурация

- **Один артефакт на все контуры** ([NC-11](../docs/01-principles/01-no-compromise.md#nc-11)).
  Дайджест образа, прошедшего stage, совпадает с уехавшим в prod — проверяется.
- Конфигурация приходит из окружения; секреты — из хранилища секретов.
- **Фронтенд получает конфигурацию в рантайме**, а не на сборке.
- Отсутствие обязательной переменной — отказ при старте, а не неявное поведение
  по умолчанию. (Так уже сделано в `bridge` — образец.)
- Ни одного адреса, порта, имени хоста в исходниках и в бандле; проверяется в CI.

## Данные в непроизводственных контурах

- Копирование промышленных данных — только с обезличиванием, автоматическим и
  проверяемым.
- Инструмент обезличивания — часть монорепозитория, покрыт тестами: ошибка в нём
  означает утечку.
- Доступ к промышленным данным — по заявке, с журналированием.

## Сеть и доступ

- TLS на всех внешних соединениях без исключений, включая внутренние контуры.
- Внутренняя топология не раскрывается клиенту.
- Интерактивный доступ к контейнерам приложения в проде закрыт по умолчанию;
  диагностика — через наблюдаемость ([product/11-observability.md](11-observability.md)).
- Изменения в проде — только через пайплайн ([NC-13](../docs/01-principles/01-no-compromise.md#nc-13)).

## Инфраструктура как код

- Все контуры описаны кодом в монорепозитории (`ops/` по
  [ADR-0007](../docs/02-decisions/ADR-0007-repo-layout.md)).
- Изменение инфраструктуры — через PR, с ревью.
- Контур воспроизводим с нуля из репозитория; проверяется созданием временного
  контура.

## Резервное копирование

- Регулярные копии промышленной БД и файлового хранилища.
- **Восстановление проверяется учениями**, а не предполагается. Резервная копия,
  из которой ни разу не восстанавливались, — не резервная копия.
- RPO и RTO — [product/07-nfr.md](07-nfr.md#доступность),
  подтверждение [OQ-006](../transition/12-open-questions.md).
- На период переезда действует отдельный порядок —
  [transition/07-cutover.md](../transition/07-cutover.md).
