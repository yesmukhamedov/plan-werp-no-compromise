# Фронтенд

Веб-приложение: из каких страниц оно состоит и из каких компонентов эти страницы
собираются. Стек — [ADR-0004](../docs/02-decisions/ADR-0004-frontend-stack.md).
Полный состав страниц по доменам — в [spec/](spec/README.md).

---

# Часть I. Правила

## Структура приложения

```
src/
  app/                    точка входа, маршрутизация, провайдеры, конфигурация из рантайма
  shared/
    ui/                   дизайн-система: компоненты без знания о домене
    api/                  СГЕНЕРИРОВАННЫЙ из спецификации клиент — руками не правится
    lib/                  форматирование, локали, деньги, даты
  features/               переиспользуемые фрагменты поведения (фильтр, экспорт, выбор)
  pages/
    <domain>/
      <page>/
        index.tsx         страница
        model.ts          состояние страницы
        ui/               компоненты, существующие только на этой странице
```

Правила:

- `pages/<domain>` соответствует домену из [карты](02-domains.md) один к одному;
- страница не импортирует ничего из другой страницы: общее поднимается в
  `features/` или `shared/`;
- `shared/ui` не знает о доменах вообще;
- **`shared/api` генерируется** из спецификации
  ([ADR-0005](../docs/02-decisions/ADR-0005-contract-first-api.md)); рукописных
  обёрток над HTTP не существует;
- маршруты объявляются рядом со страницами, а не в едином файле.

## Пять типов страниц

В ERP страницы однотипны. Тип определяет структуру, поведение и набор
компонентов; произвольная страница — исключение, требующее обоснования.

### Тип L — список

Основной тип, ~60 % страниц.

| Элемент | Обязателен | Поведение |
|---|---|---|
| Панель фильтров | да | явные именованные фильтры, состояние в URL |
| Строка поиска | если применимо | серверный поиск с задержкой ввода |
| Таблица | да | серверная пагинация, сортировка, закрепление колонок, виртуализация |
| Действия над строкой | да | по правам пользователя |
| Массовые действия | если применимо | с подтверждением |
| Выгрузка | если применимо | **серверная**, через `platform-report` |
| Кнопка создания | если применимо | по праву |

Состояние фильтров, сортировки и страницы живёт **в URL**: ссылку на
отфильтрованный список можно отправить коллеге, а «назад» в браузере
возвращает туда, где были.

### Тип C — карточка

Просмотр одной сущности: заголовок с ключевыми полями, вкладки со связанными
сущностями, история изменений (из `platform-audit`), действия по состоянию.

### Тип F — форма

Создание и редактирование. Валидация по схеме из спецификации API — та же
схема, что на сервере; ошибки сервера отображаются на соответствующих полях;
несохранённые изменения не теряются при случайном уходе со страницы.

### Тип R — отчёт

Параметры → запуск → результат. Отчёт дольше порога выполняется асинхронно:
страница показывает состояние задачи, результат приходит ссылкой
([ADR-0009](../docs/02-decisions/ADR-0009-reporting-and-exports.md)).
**Ничего не считается в браузере.**

### Тип D — панель

Сводные показатели и графики. Только чтение, без ввода.

## Дизайн-система

`shared/ui`. Одна библиотека на задачу
([NC-14](../docs/01-principles/01-no-compromise.md#nc-14)); реестр разрешённых
зависимостей проверяется в CI.

### Компоненты

| Компонент | Назначение | Ключевые свойства |
|---|---|---|
| `DataTable` | **единственная** таблица в системе | серверные пагинация/сортировка/фильтрация, закрепление колонок, виртуализация, выбор строк, сохранение настроек колонок |
| `Form` | **единственная** форма | валидация по схеме, ошибки полей, состояние отправки, защита от потери данных |
| `Field.*` | поля ввода | `Text`, `Number`, `Money`, `Date`, `DateRange`, `Select`, `Lookup`, `Checkbox`, `TextArea`, `File` |
| `Lookup` | выбор из справочника | серверный поиск, ленивая загрузка, создание на лету, отображение выбранного |
| `MoneyInput` / `MoneyText` | ввод и вывод денег | десятичная арифметика, валюта, локаль |
| `FilterBar` | панель фильтров | синхронизация с URL, сохранённые наборы фильтров |
| `PageHeader` | шапка страницы | заголовок, путь, действия |
| `Tabs` | вкладки карточки | состояние в URL |
| `Modal` / `Drawer` | диалоги | фокус-ловушка, закрытие по Esc |
| `Toast` | уведомления | не блокируют работу |
| `ConfirmDialog` | подтверждение | обязателен для необратимых действий |
| `EmptyState` | пусто | объясняет, что делать |
| `ErrorState` | ошибка | код ошибки и `traceId` для обращения в поддержку |
| `Skeleton` | загрузка | вместо «крутилки» на всю страницу |
| `Chart.*` | графики | `Line`, `Bar`, `Pie` — одна библиотека |
| `AuditTrail` | история изменений | единый вид во всех карточках |
| `PermissionGate` | показ по праву | скрывает элемент, если права нет |

Компонента с именем `CustomTable2`, `NewForm`, `TableV2` в системе не
существует. Второй компонент той же категории добавляется только через ADR.

### Работа с клавиатуры

Требование, а не улучшение: операторы ERP работают с клавиатуры, и это прямо
влияет на скорость их работы.

| Действие | Клавиши |
|---|---|
| Переход между полями | `Tab` / `Shift+Tab` в визуальном порядке |
| Сохранить форму | `Ctrl+Enter` |
| Отменить, закрыть диалог | `Esc` |
| Поиск на странице | `/` |
| Навигация по строкам таблицы | `↑` `↓` |
| Открыть строку | `Enter` |
| Выделить строку | `Space` |

Ни один сценарий не должен требовать мыши. Проверяется на приёмке.

### Доступность

Проверяется автоматически на каждом экране: контраст, видимый фокус, подписи
полей, роли и метки для вспомогательных технологий, отсутствие ловушек фокуса.

## Состояние

| Вид состояния | Где живёт |
|---|---|
| Серверные данные | кэш запросов (одна библиотека), ключ — параметры запроса |
| Состояние списка: фильтры, сортировка, страница | **URL** |
| Состояние формы | библиотека форм, локально |
| Открытые диалоги, вкладки | локальное состояние компонента |
| Пользователь, права, локаль | один контекст приложения |
| Настройки колонок таблицы | локальное хранилище браузера |

**Глобального хранилища под ответы API не существует.** Кэш запросов — не
хранилище состояния приложения, и смешивать их нельзя.

## Права в интерфейсе

- Пункт меню, кнопка и действие отображаются по праву пользователя
  (`PermissionGate`).
- Скрытие в интерфейсе — удобство, **не защита**: сервер проверяет право
  независимо ([08-security.md](08-security.md)).
- Меню строится из прав, полученных с сервера, а не из статического файла.

## Локализация

Три языка (ru / en / tr). Все тексты — из системы сообщений; строковых литералов
в компонентах нет, проверяется линтером. Числа, даты и валюты форматируются по
локали пользователя единым механизмом
([ADR-0010](../docs/02-decisions/ADR-0010-i18n.md)).

## Производительность

- Разделение бандла по маршрутам; страница загружает только своё.
- Таблицы виртуализированы: 10 000 строк не рендерятся целиком.
- Бюджет размера бандла проверяется в CI; превышение — отказ в слиянии.
- Целевые показатели — [07-nfr.md](07-nfr.md).

## Что обязано быть у каждой страницы в спецификации

- код и маршрут;
- тип (L / C / F / R / D);
- требуемое право;
- сценарии из реестра, которые она обслуживает;
- используемые эндпойнты;
- компоненты дизайн-системы;
- состояния: загрузка, пусто, ошибка, нет прав.
