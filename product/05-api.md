# Контракт API

Реализация принципов из [ADR-0005](../docs/02-decisions/ADR-0005-contract-first-api.md).
Документ фиксирует форму API так, чтобы больше тысячи эндпойнтов, написанных
разными людьми, выглядели как одно API.

---

# Часть I. Правила

## Версионирование

- Версия — в пути: `/api/v1/...`. Одна версия на всю систему, не на домен.
- В пределах версии допустимы только совместимые изменения: добавление
  необязательного поля, добавление эндпойнта, добавление значения в
  перечисление (если клиент обязан игнорировать неизвестные).
- Ломающее изменение = новая версия. Старая живёт до подтверждённого отказа
  всех клиентов.
- Совместимость проверяется автоматически на каждом PR; ломающее изменение без
  повышения версии не сливается.

## Структура пути

```
/api/v1/{домен}/{ресурс}[/{id}[/{вложенный-ресурс}[/{id}]]]
```

- `{домен}` — из [карты доменов](02-domains.md), в единственном числе.
- `{ресурс}` — существительное во множественном числе, `kebab-case`.
- Вложенность — не глубже двух уровней. Глубже — отдельный ресурс верхнего
  уровня.
- Глаголов в пути нет: действие выражается методом, а не именем ресурса.

Действия, не выражаемые через CRUD (провести документ, отменить договор,
пересчитать), оформляются как подресурс состояния:

```
POST /api/v1/contract/contracts/{id}/cancellation
POST /api/v1/accounting/postings/{id}/approval
```

а не как `POST /cancelContract`.

## Методы

| Метод | Значение | Идемпотентен |
|---|---|---|
| GET | чтение, без побочных эффектов | да |
| POST | создание или неидемпотентное действие | нет |
| PUT | полная замена | да |
| PATCH | частичное изменение | нет |
| DELETE | удаление (как правило — логическое) | да |

## Списки

**Все** списочные эндпойнты постраничные. Эндпойнта, отдающего неограниченную
выборку, в системе не существует ([01-principles/03-engineering-standards.md](../docs/01-principles/03-engineering-standards.md#производительность)).

Единые параметры:

| Параметр | Назначение |
|---|---|
| `page` / `size` или `cursor` / `limit` | постраничность; один способ на всю систему |
| `sort` | `поле:asc\|desc`, допускается несколько |
| `q` | полнотекстовый поиск по ресурсу |
| фильтры | явные именованные параметры, объявленные в спецификации |

Произвольный язык запросов в строке URL **не используется**: он делает
невозможными контроль прав по полям, предсказуемость нагрузки и автоматическую
генерацию клиента.

Ответ списка всегда одной формы: массив элементов, общее число, признак наличия
следующей страницы.

## Ошибки

Один формат на всю систему:

```json
{
  "code": "contract.not_found",
  "message": "Договор не найден",
  "details": [ { "field": "contractId", "code": "not_found" } ],
  "traceId": "..."
}
```

- `code` — машиночитаемый, стабильный, часть контракта; по нему клиент
  принимает решения.
- `message` — локализованный текст для человека ([ADR-0010](../docs/02-decisions/ADR-0010-i18n.md)).
- `traceId` — для поиска в журналах ([product/11-observability.md](11-observability.md)).
- Стек вызовов, имя класса, текст SQL и имена таблиц клиенту не уходят никогда.

Коды состояния: `400` — некорректный запрос, `401` — не аутентифицирован,
`403` — нет права, `404` — не найдено, `409` — конфликт состояния,
`422` — семантически неверно, `429` — превышен лимит, `5xx` — наша ошибка.

## Типы

| Что | Как передаётся |
|---|---|
| Дата и время | ISO 8601, UTC, с указанием зоны |
| Дата без времени | `YYYY-MM-DD` |
| Деньги | `{ "amount": "1234.56", "currency": "KZT" }` — строка, не число |
| Проценты и коэффициенты | строка с десятичным представлением |
| Идентификатор | строка; формат — решение платформы, единое для системы |
| Перечисление | строковая константа в `SCREAMING_SNAKE_CASE`, значения — часть контракта |
| Отсутствие значения | `null`; отсутствующее поле и `null` не различаются по смыслу |

Деньги передаются строкой сознательно: число с плавающей точкой в JSON теряет
точность, а весь домен D5 — денежный ([C-09](../docs/00-context/03-constraints.md#c-09-финансовые-расчёты-требуют-точной-арифметики)).

## Права

Каждый эндпойнт объявляет требуемое право прямо в спецификации
([NC-12](../docs/01-principles/01-no-compromise.md#nc-12)). Эндпойнт без объявленного
права не проходит проверку спецификации в CI.

## Слой совместимости для мобильного приложения

В системе есть **один** раздел спецификации, не подчиняющийся правилам выше:
`/api/mobile/**`. Он воспроизводит контракт, ожидаемый мобильным приложением,
которое не переписывается
([C-06](../docs/00-context/03-constraints.md#c-06-мобильное-приложение--отдельный-клиент-вне-этого-плана)).

Свойства слоя:

- реализован поверх доменных фасадов, собственной логики не содержит;
- ограничен явным списком путей — ничего сверх него не открыто;
- покрыт тестами, фиксирующими ответы 1:1;
- помечен в спецификации как устаревший, с условием вывода: обновление
  мобильного приложения.

Это единственный осознанный компромисс продукта. Он записан здесь, а не сделан
молча. Состав путей и правила соответствия —
[transition/03-api-mapping.md](../transition/03-api-mapping.md#слой-совместимости).

## Долгие операции

Операция, не укладывающаяся в бюджет времени ответа
([05-nfr.md](07-nfr.md)), возвращает `202` и идентификатор задачи; клиент
следит за состоянием отдельным эндпойнтом или получает уведомление. Так
работают тяжёлые отчёты ([ADR-0009](../docs/02-decisions/ADR-0009-reporting-and-exports.md)),
массовые загрузки и пересчёты.

## Что обязано быть у каждого эндпойнта

Проверяется линтером спецификации; без этого эндпойнт не проходит CI:

- `operationId` — уникальный, в `camelCase`;
- требуемое право ([NC-12](../docs/01-principles/01-no-compromise.md#nc-12));
- описание на русском;
- схемы запроса и ответа — ссылками на общие компоненты, не встроенные;
- перечень кодов ошибок, которые эндпойнт может вернуть;
- пример запроса и ответа;
- для списков — стандартные параметры пагинации и сортировки.
