# Проверка паритета

Механизм, компенсирующий главный недостаток big bang — отсутствие обратной связи
из прода до самого переезда ([ADR-0001](../02-decisions/ADR-0001-strategy-big-bang.md#осознанная-плата)).

**Идея:** новая система получает те же входные данные, что и старая, и её ответы
автоматически сравниваются с ответами старой. Расхождение — дефект. Так мы
получаем поток реальной обратной связи, не выпуская новую систему в прод.

Без этого механизма big bang вырождается в «полтора года пишем, потом
надеемся». Он не опционален.

## Три уровня

### Уровень 1. Сверка данных

Разовая, после каждого прогона миграции. Описана в
[02-data-migration.md](02-data-migration.md#сверка).

### Уровень 2. Теневой прогон

Непрерывный, начиная с первого готового домена и до самого переезда.

```
          запрос пользователя
                  │
                  ▼
          ┌───────────────┐
          │   легаси      │──────► ответ пользователю
          └───────┬───────┘
                  │ копия запроса (только чтение)
                  ▼
          ┌───────────────┐
          │  новый WERP   │──────► ответ отбрасывается
          └───────┬───────┘
                  ▼
          ┌───────────────┐
          │  сравнение    │──────► расхождения в отчёт
          └───────────────┘
```

Правила:

- Копируются **только запросы чтения**. Изменяющие запросы не дублируются
  никогда — новая система не должна создавать данные в этот период.
- Новая система работает на копии промышленных данных, синхронизируемой
  регулярно.
- Ответ новой системы **никогда** не доходит до пользователя.
- Сравнение — по смыслу, а не побайтно: порядок ключей, форматирование чисел и
  идентификаторы запросов из сравнения исключаются, а различия по существу —
  нет.
- Отчёт о расхождениях — ежедневный, с разбивкой по доменам и эндпойнтам.

Метрика проекта: **доля запросов с расхождением**. Она публикуется еженедельно
и является главным индикатором готовности к переезду. Условие допуска —
30 дней подряд без неразобранных расхождений.

Технически теневой прогон реализуется на уровне маршрутизации, вне обеих
систем — он не должен требовать изменений в легаси.

### Уровень 3. Сценарный паритет

Ручные и автоматизированные сквозные сценарии, выполняемые в обеих системах с
одинаковыми входными данными и сравниваемые по результату.

Покрывает то, чего теневой прогон не видит: операции записи, многошаговые
процессы, печатные формы, расчёты.

| Категория | Что сравнивается | Допуск |
|---|---|---|
| Финансовые расчёты | суммы, проводки, сальдо, налоги | **0** |
| Расчёт вознаграждений | начисления, удержания, итог по сотруднику | **0** |
| Отчёты | построчно | **0** |
| Печатные формы | состав данных (не оформление) | 0 |
| Складские операции | остатки после операции | 0 |
| Права доступа | что видит и что может пользователь роли X | 0 |
| Интерфейсные сценарии | достижимость результата, число шагов | по согласованию |

Реестр сценариев формируется в Фазе 0
([EPIC-011](../../backlog/EPIC-011-scenario-registry.md)) и является
одновременно: планом ручной приёмки, основой сквозных тестов и определением
полноты новой системы.

## Что делать с расхождением

Каждое расхождение проходит один и тот же путь:

1. **Зафиксировать** — запрос, оба ответа, домен, дата.
2. **Классифицировать:**
   - *дефект новой системы* → задача, исправляется;
   - *дефект старой системы* → **осознанное расхождение**, требует письменного
     решения бизнеса: воспроизводим ошибку или исправляем;
   - *намеренное изменение* → должно быть заранее описано в задаче; если не
     описано — это не намеренное изменение, а дефект;
   - *артефакт сравнения* → чинится инструмент сравнения.
3. **Закрыть** — исправлением или письменным принятием.

**Ключевое правило: «в старой системе так же неправильно» не является
основанием закрыть расхождение молча.** Решение воспроизвести ошибку старой
системы принимает бизнес и записывает его. Иначе через год никто не вспомнит,
почему цифра такая.

За 12 лет в системе накопились поведения, которые пользователи считают
правильными, а разработчики — ошибками, и наоборот. Теневой прогон делает их
видимыми — это его вторая, не менее ценная функция.

## Отчётность

Еженедельно, на всём протяжении Фаз 2–4:

| Показатель | Смысл |
|---|---|
| Доля запросов с расхождением, по доменам | готовность домена |
| Число неразобранных расхождений | долг |
| Число принятых осознанных расхождений | сколько ошибок старой системы воспроизводим |
| Покрытие сценарного реестра | полнота проверки |
| Дней подряд без новых расхождений | зрелость |

Эти цифры — единственный объективный индикатор прогресса при big bang. Проценты
готовности, названные разработчиками, таким индикатором не являются.
