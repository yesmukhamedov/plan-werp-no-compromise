# Целевая архитектура

Документ описывает, как устроен новый WERP. Конкретные технологии не названы:
решение по стеку отложено ([ADR-0003](../02-decisions/ADR-0003-backend-stack.md)),
и всё описанное здесь выполнимо на любом из кандидатов. Места, где стек всё же
влияет, помечены `[STACK]`.

## Общая схема

```
        браузер                мобильное приложение        внешние системы
           │                            │                         │
           │                            └────────┬────────────────┘
           │                                     ▼
           │                              ┌─────────────┐
           │                              │   bridge    │  Go, не переписывается
           │                              └──────┬──────┘
           ▼                                     │
   ┌───────────────┐                             │
   │  веб-фронтенд │                             │
   │  (статика)    │                             │
   └───────┬───────┘                             │
           │                                     │
           └──────────────┬──────────────────────┘
                          ▼
                 ┌──────────────────┐
                 │ провайдер        │  аутентификация (ADR-0006)
                 │ идентичности     │
                 └────────┬─────────┘
                          ▼
        ┌─────────────────────────────────────────┐
        │            приложение WERP              │  модульный монолит (ADR-0008)
        │  ┌───────────────────────────────────┐  │
        │  │  платформа: доступ, аудит,        │  │
        │  │  отчёты, файлы, уведомления,      │  │
        │  │  фоновые задачи, наблюдаемость    │  │
        │  └───────────────────────────────────┘  │
        │  ┌────────┬────────┬────────┬────────┐  │
        │  │ домен  │ домен  │ домен  │  ...   │  │  границы проверяются машиной
        │  └────────┴────────┴────────┴────────┘  │
        └────────────────────┬────────────────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
   PostgreSQL          хранилище файлов       очередь задач
   (схема на домен)                           + обработчик
```

## Слои

Внутри каждого домена — три слоя и одно правило зависимостей: **внутрь, никогда
наружу**.

| Слой | Что содержит | От чего зависит |
|---|---|---|
| Доменный | сущности, правила, инварианты, доменные операции | ни от чего внешнего |
| Прикладной | сценарии, границы транзакций, авторизация, оркестрация | от доменного |
| Адаптеры | HTTP, хранилище, очереди, внешние системы, файлы | от прикладного |

Доменный слой не знает ни про HTTP, ни про базу. Именно это делает его
тестируемым без контейнера и без базы — и именно это отсутствует в текущей
системе, где `ContractController` содержит бизнес-логику вперемешку с
транспортом.

## Модули и границы

Система делится на модули по [карте доменов](02-domain-map.md). Каждый модуль:

- имеет **узкий явный публичный интерфейс** — всё остальное недоступно снаружи
  технически `[STACK]`;
- имеет **собственную схему** в PostgreSQL; чужие таблицы не читает;
- ссылается на сущности других модулей **по идентификатору**, без внешних ключей
  через границу;
- имеет владельца — человека;
- имеет README ([01-principles/03-engineering-standards.md](../01-principles/03-engineering-standards.md#структура-модуля)).

Нарушение границы обнаруживается тестом архитектурных правил и блокирует
слияние ([NC-02](../01-principles/01-no-compromise.md#nc-02)).

## Междоменное взаимодействие

Два способа, и только они:

1. **Синхронный вызов публичного интерфейса** — когда результат нужен сейчас и
   операция логически едина. Внутри монолита это обычный вызов в той же
   транзакции.
2. **Доменное событие** — когда другой домен должен отреагировать, но
   инициатору его результат не нужен. Событие публикуется в рамках транзакции
   источника; подписчики обрабатывают его отдельно, с гарантией доставки
   (транзакционный исходящий журнал).

Запрещено: чтение чужих таблиц, внедрение чужого репозитория, общая изменяемая
структура данных между доменами.

## Платформа

Слой, общий для всех доменов. Пишется в Фазе 1 **до** доменной разработки —
иначе каждый домен построит свой вариант, как произошло с текущими `util` и
`main-module`.

| Подсистема | Ответственность |
|---|---|
| Доступ | аутентификация, права, область данных ([ADR-0006](../02-decisions/ADR-0006-auth-model.md)) |
| Аудит | кто, что, когда изменил ([C-10](../00-context/03-constraints.md#c-10-аудит-изменений-уже-существует-и-должен-сохраниться)) |
| Отчёты и выгрузки | шаблоны, формирование, асинхронное исполнение ([ADR-0009](../02-decisions/ADR-0009-reporting-and-exports.md)) |
| Файлы | загрузка, хранение, доступ, срок жизни |
| Уведомления | почта, SMS, сообщения в мессенджерах, уведомления в интерфейсе |
| Фоновые задачи | расписание, очередь, повторы, идемпотентность |
| Наблюдаемость | журналы, метрики, трассировка ([06-quality/03-observability.md](../06-quality/03-observability.md)) |
| Справочная инфраструктура | общий механизм справочников, поиска, кэширования |
| Ошибки и валидация | единая модель ошибки, локализованные сообщения |

## Данные

- Одна база PostgreSQL, схема на домен ([ADR-0002](../02-decisions/ADR-0002-database-postgresql.md)).
- Схема меняется только версионированными миграциями; автогенерация в рантайме
  запрещена во всех контурах.
- Тяжёлое чтение (отчёты, аналитика) — с реплики.
- Кэш — явный, с понятной политикой инвалидации; кэш не является источником
  истины и его потеря не приводит к некорректным данным.

Подробно — [04-data-model.md](04-data-model.md).

## Развёртывание

| Компонент | Экземпляров | Профиль |
|---|---|---|
| Приложение WERP | несколько, за балансировщиком | обработка запросов |
| Обработчик фоновых задач | отдельно, та же кодовая база | длительные операции, расписание |
| Веб-фронтенд | статика за CDN/веб-сервером | — |
| `bridge` | как сейчас | внешняя граница |

Один и тот же артефакт проходит все контуры; различия только в конфигурации
([NC-11](../01-principles/01-no-compromise.md#nc-11)).

## Чего в архитектуре намеренно нет

| Не будет | Почему |
|---|---|
| Микросервисов | [ADR-0008](../02-decisions/ADR-0008-modular-monolith.md) |
| Общей БД между независимо развёртываемыми частями | причина текущего распределённого монолита |
| Второй реализации домена | [NC-06](../01-principles/01-no-compromise.md#nc-06) |
| Собственного сервера аутентификации | [ADR-0006](../02-decisions/ADR-0006-auth-model.md) |
| Формирования отчётов в браузере | [ADR-0009](../02-decisions/ADR-0009-reporting-and-exports.md) |
| Слоя `util`, куда складывают всё подряд | так появился текущий `util`, а за ним `main-module` |
| Прямого доступа фронтенда к нескольким разным бэкендам | причина захардкоженных адресов в бандле |
