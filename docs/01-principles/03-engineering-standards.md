# Инженерные стандарты

Правила [NC-01…NC-15](01-no-compromise.md) говорят, чего нельзя. Этот документ
говорит, как принято делать. Он стек-нейтрален: конкретные инструменты
подставляются после [ADR-0003](../02-decisions/ADR-0003-backend-stack.md).

## Репозиторий и ветки

- Один репозиторий на компонент верхнего уровня; структура определяется
  [ADR-0007](../02-decisions/ADR-0007-repo-layout.md).
- `main` всегда в состоянии, пригодном для сборки и развёртывания.
- Работа — в короткоживущих ветках, слияние через PR, прямой push в `main`
  запрещён технически.
- Коммит-сообщения — Conventional Commits; из них собирается журнал изменений.

## Ревью

- Минимум один ревьюер, не автор.
- Ревьюер отвечает на три вопроса: правильно ли решена задача, не нарушены ли
  правила, поймёт ли это следующий человек через год.
- PR больше ~400 изменённых строк разбивается, если это возможно.

## Структура модуля

Каждый модуль системы имеет одинаковую форму. Образец — репозиторий `bridge`:
README, объясняющий назначение, принципы и структуру; разделение по осям «кто
вызывает» и «с кем интегрируемся»; тесты рядом с кодом; конфигурация из
переменных окружения с проверкой обязательных значений на старте.

Обязательный минимум модуля:

```
README.md          назначение, принципы, структура, как запустить, как тестировать
<публичный API>    то, что видят другие модули — явно и узко
<домен>            бизнес-логика, не зависящая от транспорта и хранилища
<адаптеры>         хранилище, HTTP, очереди, внешние системы
<тесты>            рядом с кодом, запускаются одной командой
```

README модуля обязателен и обновляется вместе с кодом. Модуль без README не
сливается.

## Именование

- Одна доменная сущность — одно имя во всей системе: в коде, в API, в схеме
  данных, в интерфейсе и в разговоре. Глоссарий — [GLOSSARY.md](../../GLOSSARY.md).
- Транслитерация в именах запрещена: либо русское понятие переведено в глоссарии
  один раз, либо используется как есть — но не `bukrs`, `matnr`, `lifnr` и не
  `srok_dogovora`. Текущие имена полей унаследованы от чужой ERP и требуют
  расшифровки в глоссарии перед переносом.
- Имена в схеме данных — `snake_case`, единственное число для сущности.

## Ошибки

- Одна модель ошибки на всю систему: машиночитаемый код, человекочитаемое
  сообщение, идентификатор запроса для поиска в журналах.
- Ошибка не «проглатывается»: либо обрабатывается, либо пробрасывается с
  контекстом.
- Клиенту не уходит стек вызовов, имя класса, текст SQL или имя таблицы.

## Работа с временем и деньгами

- Время хранится в UTC, отображается в часовом поясе пользователя. Часовой пояс
  не зашивается в образ.
- Деньги — только десятичный тип фиксированной точности, никогда не число с
  плавающей точкой. Правила округления определены один раз на платформе
  ([product/03-database.md](../../product/03-database.md)) и не
  переопределяются в доменах.
- Валюта хранится вместе с суммой.

## Миграции схемы

- Только вперёд, только версионированно, только через инструмент миграций.
- Каждая миграция обратимо применима на копии промышленных данных до слияния.
- Изменения, ломающие совместимость, разбиваются на шаги (добавить → заполнить →
  переключить → удалить).
- `ddl-auto` и любая автогенерация схемы в рантайме запрещены во всех контурах.

## Производительность

- Каждый список — с пагинацией; эндпойнтов, возвращающих неограниченную выборку,
  не существует.
- Запросы к БД профилируются на реалистичном объёме данных, а не на пустой базе.
- Проблема N+1 отлавливается тестом, а не на проде.
- Отчёты и выгрузки, работающие дольше порога, выполняются асинхронно с
  уведомлением пользователя.

## Безопасность

- Секреты — только из хранилища секретов, никогда в репозитории, образе или
  журнале.
- Внешний трафик — только TLS.
- Каждый эндпойнт объявляет требуемое право (NC-12).
- Входные данные валидируются на границе, а не в глубине логики.
- Подробнее — [product/08-security.md](../../product/08-security.md).

## Документация

- Документация живёт рядом с кодом и меняется вместе с ним.
- Архитектурные решения — только ADR, по одному файлу на решение.
- Спецификация API генерируется из контракта, а не пишется вручную
  ([ADR-0005](../02-decisions/ADR-0005-contract-first-api.md)).
- Документ, который никто не читает, удаляется, а не «поддерживается».
