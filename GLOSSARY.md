# Глоссарий

Одна доменная сущность — одно имя во всей системе: в коде, в API, в схеме
данных, в интерфейсе и в разговоре
([01-principles/03-engineering-standards.md](docs/01-principles/03-engineering-standards.md#именование)).

Глоссарий пополняется по ходу проекта. Раздел «Унаследованные имена» заполняется
в [EPIC-003](backlog/EPIC-003-schema-inventory.md), раздел «Домены» уточняется
вместе с бизнесом до гейта G1.

---

## Термины плана

| Термин | Значение |
|---|---|
| **WERP** | внутренняя ERP-система, предмет переписывания |
| **Легаси** | все три поколения текущей системы, подлежащие замене |
| **Новый WERP** | целевая система |
| **Big bang** | стратегия перехода: параллельная разработка, один переезд ([ADR-0001](docs/02-decisions/ADR-0001-strategy-big-bang.md)) |
| **Переезд (cutover)** | момент перевода пользователей на новую систему |
| **Теневой прогон** | дублирование запросов чтения в новую систему со сравнением ответов ([transition/06-parity-verification.md](transition/06-parity-verification.md)) |
| **Паритет** | доказанная эквивалентность поведения новой и старой системы |
| **Осознанное расхождение** | различие в поведении, принятое письменно бизнесом |
| **Заморозка** | ограничение изменений в легаси на время проекта ([transition/09-freeze-policy.md](transition/09-freeze-policy.md)) |
| **Delta backlog** | задачи нового WERP, порождённые изменениями в легаси во время заморозки |
| **Гейт** | контрольная точка с формальными условиями прохождения ([transition/plan/00-roadmap.md](transition/plan/00-roadmap.md#гейты)) |
| **Характеризационный тест** | тест, фиксирующий текущее поведение легаси, включая ошибки ([EPIC-004](backlog/EPIC-004-characterization-tests.md)) |
| **Репетиция** | полный прогон миграции данных на копии промышленных данных |
| **Точка принятия решения** | момент в ходе переезда, после которого откат становится дорогим |
| **NC-NN** | правило «без компромиссов» ([01-principles/01-no-compromise.md](docs/01-principles/01-no-compromise.md)) |
| **P-NN** | точка боли текущей системы ([00-context/02-pain-points.md](docs/00-context/02-pain-points.md)) |
| **`[STACK]`** | пометка: зависит от невыбранного стека бэкенда ([ADR-0003](docs/02-decisions/ADR-0003-backend-stack.md)) |

## Унаследованные имена

Сокращения из схемы текущей системы, унаследованные от чужой ERP. Заполняется в
[TASK-0309](backlog/EPIC-003-schema-inventory.md).

Транслитерация в новой системе запрещена: каждое сокращение получает
осмысленную замену.

| Старое | Значение | Новое имя |
|---|---|---|
| `bukrs` | требует расшифровки | — |
| `matnr` | требует расшифровки | — |
| `lifnr` | требует расшифровки | — |
| `werks` | требует расшифровки | — |
| `aes` | назначение модуля неизвестно — [OQ-004](transition/12-open-questions.md#oq-004) | — |
| `newdev` | назначение модуля неизвестно — [OQ-004](transition/12-open-questions.md#oq-004) | — |
| `dit` | внутреннее ИТ: задачи, сообщения, SMS, ABAC | — |
| `mreference` | вторая реализация справочников | — |

> Таблица заполняется опросом носителей знания, а не догадками. Догадка,
> попавшая в схему, живёт двенадцать лет — что и произошло с исходными
> сокращениями.
